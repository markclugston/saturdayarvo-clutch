# Research: Exclude Pending Authorisations From Imports

## R1 Chronological prior row when authorisations break balance reconciliation

- **Unknown**: The spec's "prior row" uses `ImportOrdering` file-direction rules. `InferDirection` picks a direction from balances only when every adjacent pair reconciles in exactly one direction. An authorisation row (non-zero amount, unchanged balance) never reconciles, so in any file containing one the balance signal is lost and the rule falls back to first/last dates, which cannot tell direction for a single-date file.
- **Decision**: `ImportExclusions` evaluates both directions. For each direction it walks rows in the file's running order, earliest first (file order for oldest-first, reversed for newest-first), ignoring dates, and marks every row with a non-zero amount whose balance equals the previous row's balance (both balances present). It chooses the direction whose remaining rows reconcile (`ImportOrdering.InferDirection` on the remaining rows returns that direction from balances). If neither or both qualify, it uses `InferDirection` over all rows (existing fallback) and that direction's exclusions. It returns the chosen direction and the excluded row numbers.
- **Use**: Review creation stores the excluded flags. Confirm calls the same rule on the stored rows and mapping to get the direction, orders only non-excluded rows in it, and saves them. Identical inputs give identical results, so stored flags and confirm ordering agree.
- **Rationale**: Keeps the existing ordering rules unchanged for files without authorisations, and restores the balance signal for files with them.
- **Alternatives rejected**: Using `InferDirection` over all rows (loses direction for single-date files with an authorisation); comparing with the row above in every file (wrong for newest-first files); ordering by date before comparing (the first version: a real file listed an authorisation dated 26 Nov among 30 Nov rows, so it was compared with the wrong row and imported).
