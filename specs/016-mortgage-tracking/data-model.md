# Data Model: Mortgages Screen

## Mortgage (`Mortgages` table)

| Field | Type | Rules |
|---|---|---|
| Id | `uniqueidentifier` PK | Generated by the domain |
| OwnerUserId | `nvarchar(450)` FK → AspNetUsers (Restrict) | Signed-in user; every query filters on it |
| Name | `nvarchar(100)`, collation `Latin1_General_100_CI_AS` | Trimmed; 1–100 chars; unique per owner ignoring case (index + check `LEN(LTRIM(RTRIM(Name))) > 0`) |
| StartingBalance | `decimal(19,2)` | > 0, ≤ 999,999,999,999.99, ≤ 2 dp |
| NumberOfPeriods | `int` | ≥ 1; final repayment date ≤ 31 Dec 9999 |
| FirstRepaymentDate | `date` | Valid; ≤ today (R5) |
| RepaymentFrequency | `nvarchar(20)` (enum as string) | `Weekly` \| `Fortnightly` \| `Monthly` |
| CreatedAtUtc | `datetimeoffset` | Creation order for tabs (tie-break: Id) |
| Version | `int`, concurrency token | Starts at 1; +1 on every update (R4) |

Indexes: unique `(OwnerUserId, Name)`; `(OwnerUserId, CreatedAtUtc)`.

Limit: ≤ 20 per owner (checked in a serializable create transaction, R6).

## InterestRateChange (`MortgageInterestRateChanges` table)

| Field | Type | Rules |
|---|---|---|
| Id | `uniqueidentifier` PK | |
| MortgageId | FK → Mortgages, cascade delete | |
| NewInterestRate | `decimal(5,2)` | 0–100, ≤ 2 dp |
| EffectiveDate | `date` | First repayment date ≤ date ≤ final repayment date; unique per mortgage |

Indexes: unique `(MortgageId, EffectiveDate)`.

Rules across the set: 1–60 rows; one row's EffectiveDate equals FirstRepaymentDate (opening rate);
rows only accepted when FirstRepaymentDate, NumberOfPeriods and RepaymentFrequency are valid.
Returned in EffectiveDate order. On update the set is replaced (owned collection; rows removed and
added in the same `SaveChanges`).

## Derived (not stored)

- **Final repayment date** = date of period N (R10). Used only for validation.
- **Amortization schedule row** (UI only): Period 1..N+1, Date, Bank schedule — placeholders.

## State transitions

`(none) → Created (Version 1) → Updated (Version n+1)… → Deleted`. Update/Delete require the
caller's Version to equal the stored one, else 409. Every successful update increments Version and
writes one `MortgageUpdate` audit row, even when no value changed (spec FR-020).

## Audit (existing `Audit` table, append-only)

| Operation | EventCode | Description (no balances or rates) |
|---|---|---|
| Create | `MortgageCreate` | `Mortgage {Name} was created.` |
| Update | `MortgageUpdate` | `Mortgage {Name} was updated.` (or `…renamed from {Old} to {New}.`) |
| Delete | `MortgageDelete` | `Mortgage {Name} was deleted.` |

Written in the same `SaveChanges` as the change, so exactly one per successful operation.

## Migration

`*_Mortgages`: creates both tables, FKs and indexes. No existing data touched. Rollback: `Down`
drops `MortgageInterestRateChanges` then `Mortgages` (loses only mortgage data; audit rows remain).
